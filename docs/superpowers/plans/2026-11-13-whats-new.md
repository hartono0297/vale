# What's new per patch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After Vale updates, a clickable "Diperbarui ke X.Y.Z" notice opens a "Apa yang baru" card in Settings → Tentang with the hand-written changes of every version since the last one seen.

**Architecture:** A compiled-in table (`src/whats_new.rs`) holds one entry per version (ID and EN points); a test fails when `Cargo.toml`'s version has no entry. `config.whats_new_seen` remembers the last version shown. At a release start, `whats_new::start_action` decides: quiet, store only, or show. "Show" raises a new `NoticeKind::WhatsNew` whose body click gives `Effect::OpenWhatsNew`, which opens Settings on the new `CardId::WhatsNew` (Tentang).

**Tech Stack:** Rust 2024, Win32 + Direct2D, existing Settings layout builder, `cargo test --locked`.

**Spec:** `docs/superpowers/specs/2026-11-13-whats-new-design.md`

## Global Constraints

- Windows 11 x64 only; no new crates; no network; no new window; no new timer.
- Entry = `version` + 1-5 points per language, none empty; table newest first, versions strictly descending.
- Never shown in debug builds, demos, or on a fresh install (`!config.onboarding_done` and `whats_new_seen` empty).
- Shown once: `whats_new_seen` is stored at the moment the notice is raised.
- `whats_new_seen` is PC-only: never exported/imported (`config_transfer::LEFT_OUT`), kept by `config::merge_owned`, read leniently (`lenient_string`).
- UI text in both languages through `i18n` (`Key` with `"id", "en"`); Indonesian is the base wording, plain and short.
- Notice wording: title `update_done(lang, current)` ("Diperbarui ke X.Y.Z"), body `"{old} → {new} · klik untuk lihat apa yang baru"` (English: `"… · click to see what's new"`); without an old version the body is only the hint.
- Match the code's existing style, comments explain why; every changed line traces to this plan.
- Commit after each task with the trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. `whats_new_seen` newer than the running version (downgrade) or garbage (`"abc"`, `"5.3"`): no crash, downgrade stores and shows nothing, garbage on an existing install shows only the current entry once. (Task 1.)
2. Fresh install that quits before onboarding ends: the next start must stay silent (seen already stored). (Task 5.)
3. Skipped versions (5.3.1 → 5.3.4, or a table with gaps): entries in range listed newest first; a range with no entry raises no notice. (Task 1.)
4. Settings already open on another section when the notice is clicked: it must move to Tentang and scroll to the card. (Task 3.)
5. Long Indonesian points, JetBrains Mono, Settings at its minimum width: card rows wrap inside the card, no clipped or overlapping text. (Task 4.)

### Task 1: The table and its rules

**Files:**
- Create: `src/whats_new.rs`
- Modify: `src/main.rs` (add `mod whats_new;` next to `mod update;`)

**Interfaces:**
- Produces:
  - `pub struct Entry { pub version: &'static str, pub id: &'static [&'static str], pub en: &'static [&'static str] }`
  - `pub static ENTRIES: &[Entry]` (newest first; first entry is `5.3.1`)
  - `pub fn points(entry: &Entry, lang: Lang) -> &'static [&'static str]` (`crate::i18n::Lang`)
  - `pub fn since(seen: &str, current: &str) -> Vec<&'static Entry>`: entries with `seen < version <= current`, newest first; when `seen` does not parse, only the entry whose version equals `current`.
  - `pub fn latest(n: usize) -> &'static [Entry]`: the first `min(n, len)` entries.
  - `pub enum StartAction { None, Store, Show }` and `pub fn start_action(seen: &str, current: &str, fresh: bool) -> StartAction`.
  - Uses `crate::update::parse_version(&str) -> Option<(u32, u32, u32)>`.

- [ ] **Step 1: Write the failing tests** in `src/whats_new.rs` (`#[cfg(test)] mod tests`), with a private test table where a rule needs one. Names and assertions:
  - `table_has_an_entry_for_the_running_version`: `ENTRIES.iter().any(|e| e.version == env!("CARGO_PKG_VERSION"))`, message "write the What's new entry in src/whats_new.rs before bumping the version".
  - `table_is_well_formed`: every `version` parses; versions strictly descending; `id` and `en` each 1..=5 points; no point empty or longer than 90 chars.
  - `since_lists_the_range_newest_first`: over a fixture table via a private `since_in(entries, seen, current)`; `("5.3.1","5.3.4")` → `[5.3.4, 5.3.3, 5.3.2]`; `("5.3.4","5.3.4")` → empty; a gap (no 5.3.3 entry) → only the existing ones; no entry in range → empty.
