# Tooltips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One themed Vale tooltip (name, hotkey, what a click does) on every icon-only or unclear button in Vale's own windows.

**Architecture:** A pure state machine and placement maths (`ui/tooltip/logic.rs`) drive one layered, click-through, no-activate popup (`ui/tooltip/mod.rs`) that exists only while a tip shows. Every window reports hover, press and leave to it with a `Target` (screen-px anchor + `Tip`); per-surface `*_tip` functions map a hit to its `Tip` from i18n keys.

**Tech Stack:** Rust 2024, `windows` crate (Win32, Direct2D, DirectWrite), the existing `shot_edit::gfx::Gfx`, `arrange_overlay::Canvas`, `theme::current_window()`, `i18n` `keys!` macro.

**Spec:** `docs/superpowers/specs/2026-11-12-tooltips-design.md` (read it: the tables there are the exact tooltip texts).

## Global Constraints

- Look: `popover` fill, 1 px `border` hairline, soft shadow as `ui/menu_pop.rs`; name weight 600 ~12.5 dip in `text`; key plate `button` fill, `text`, weight 600 ~10.5 dip at the right end of line 1; about line `secondary` ~12 dip, wrapping; plate at most 280 dip wide. Short form (button already labelled): no name, about in `text` colour.
- Timing: show after 500 ms rest; while a tip is up or within 300 ms after one went away, another tip shows at once. Hide at once on leave, any press, wheel, key, drag start, owner hide / move / resize / region loss, theme or language change. After a click a button shows no tip until the pointer has left it.
- Place: centred below the anchor, 6 dip gap; above when no room below in the work area of the anchor's monitor; pushed sideways inside it. `Side::Below` (closed notch) never flips. Sizes use the anchor monitor's DPI.
- Window: one per app, `WS_POPUP`, `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TOPMOST`, `HWND_TOPMOST` asserted on every show without activation, created on show and destroyed on hide. Timers: thread timers (`SetTimer(None, …)`) that exist only while waiting or warm. No animation.
- Text: every string an i18n `Key` (both languages), no em dash, hotkeys resolved from the live config at show time, a hotkey with no combo shows no plate.
- Never on screen in tests (`ON_SCREEN = !cfg!(test)`, see [[test-spawns-no-window]]).
- No timer, thread or window at idle (`bata-idle-power-budget`).
- Do not change what any button does, any hit area that takes clicks, or the island's hover / linger logic.

## Review Focus

- Owner moves or hides while a tip shows (sticky note drag, panel collapse, card resize): the tip must go at once, never float detached. Pinned in Task 1 (`hide` and `press` tests) and Task 3 / Task 5 (drag start, region loss call `hide`).
- Anchor at a screen edge or in the closed notch at the very top: the tip stays fully inside the work area and the notch tip never goes above. Pinned in Task 1 placement tests.
- Mixed DPI: an anchor on a 150 % monitor sizes the plate with 1.5, not the primary's scale. Pinned in Task 2 (`plate_px` test).
- A hotkey changed or cleared in Settings while Vale runs: the next tip shows the new combo or no plate. Pinned in Task 2 (`resolve_keys` test).
- A very long dynamic name (Mixer app name): line 1 is cut with an ellipsis inside 280 dip, the about line wraps; the plate never exceeds 280 dip. Pinned in Task 2 (`plate_w` test).

  - `#[derive(Clone, Copy, Debug, PartialEq, Eq)] pub struct TipId { pub owner: isize, pub id: u64 }`
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq)] pub enum Side { Auto, Below }`

- New i18n keys: `TipKeySpace` ("Spasi" / "Space"), `TipKeyRightClick` ("Klik kanan" / "Right-click"), `TipKeyWheel` ("Roda mouse" / "Mouse wheel").

The pending `Target` (text + anchor) is kept with the Machine in a `thread_local!`; `hover` stores the newest target for the hovered id. On `Out::show` the module measures (UI font from the current config, sizes from the spec), places with `logic::place` on the anchor monitor's work area (`monitor_at` of the anchor centre), creates the window (`Some(owner)` as owner, styles from Global Constraints), paints once into a `Canvas` (`UpdateLayeredWindow`), shows with `SW_SHOWNOACTIVATE` and `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE|SWP_NOMOVE|SWP_NOSIZE)`. `Out::hide` destroys it. `arm_ms` / `kill` map to one `SetTimer(None, 0, ms, Some(proc))` / `KillTimer`. Line 1 is cut with an ellipsis (`Text::line`); the about line wraps (`Text::block`) inside `plate_w`.

Wiring in `app.rs`: call `tooltip::set_hotkeys(config.hotkeys)` at startup and wherever the config is applied; call `tooltip::hide_all()` where the theme or language changes (next to `theme::set_current` / `i18n::set_lang`), where a screenshot capture starts (`app_shot.rs` / `app_prtsc.rs` start path) and where the screen-recording picker opens (`app_screenrec.rs`).
