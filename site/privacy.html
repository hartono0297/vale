Privacy policy

Last updated: 1 November 2026

In short

  • Vale runs on your PC. There is no Vale server and no account.
  • Vale has no telemetry, no analytics, no crash reports and no update checker.
  • Your data stays on your PC. The only exceptions are the opt-in connections listed in the network section: Google Calendar, lyrics from LRCLIB, and the web search page that opens in your browser.
  • Google Calendar is off until you sign in. What Vale gets from Google goes only between your PC and Google.

Google user data

Google Calendar is optional. Vale does not contact Google until you choose to sign in.

How sign-in works

Vale opens the Google sign-in page (accounts.google.com) in your default browser and uses PKCE. After you approve, Vale exchanges the sign-in code for a token with oauth2.googleapis.com. While you sign in, Vale listens on the loopback address 127.0.0.1 so the browser can hand the code back. That listener exists only during sign-in and cannot be reached from other computers.

Release builds use Vale's own OAuth client. If you enter a Client ID in Settings > Integrations, Vale uses yours instead.

What Vale asks Google for

Vale requests two permissions (scopes):

  • https://www.googleapis.com/auth/calendar.calendarlist.readonly: Vale reads the list of your calendars and their colours, so events can be shown per calendar.
  • https://www.googleapis.com/auth/calendar.events: Vale reads your events to show them, creates new events in your primary calendar, and edits an existing event when you change it in Vale.

Vale never deletes events. Read-only events, recurring events and multi-day events cannot be edited in Vale. While you are connected, Vale asks Google for your calendars and events again every 10 minutes.

Where it is stored

  • The sign-in token is in %APPDATA%\Vale\google-token.bin, encrypted with Windows DPAPI for your Windows account.
  • The calendar cache is %APPDATA%\Vale\calendar-cache.json. It is plain JSON with event titles, times, descriptions and calendar colours. Vale keeps it after you disconnect, until you delete it (see Deleting your data).

Who sees it

Google user data moves only between your PC and Google. Vale never sends it to the developer or to anyone else. It is not sold. It is not used for advertising or profiling, and not used to train artificial intelligence or machine-learning models. No person reads it, because there is no server for it to arrive on.

Limited Use

Vale's use and transfer of information received from Google APIs to any other app will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

What Vale reads from Windows

Vale reads the following from Windows on your PC. None of it is sent anywhere.

  • Windows notifications, to show them in the notch and keep a history. Vale never removes them from the Action Center.
  • The track that is playing, from the Windows media session.
  • The clipboard, for the clipboard history and the copy preview.
  • Audio loopback of your default output, for the equalizer bars. Vale keeps five levels in memory and no audio. This is on by default.
  • Per-app volume, for the Mixer.
  • A low-level keyboard hook that reacts only to the bare PrtSc key, to open Vale's screenshot capture. This is on by default. Vale checks each key only to see whether it is PrtSc; it does not record or keep any other key.
  • Hotkeys Vale registers with Windows. Search on Ctrl+Alt+Space is on by default.
  • Removable devices, for the Devices page and safe eject.
  • UI Automation element boxes, so a screenshot can snap to windows and controls.
  • Explorer folders and Start Menu shortcuts, and the names of files in Desktop, Documents, Downloads, Pictures, Videos and Music, for search.
  • Battery, CPU, memory, disks and running processes, for the System page.
  • The pointer position, so the cat can look at it and the notch can react to it.

Deleting your data

  • Disconnect Google. Settings > Integrations > Disconnect deletes the token file only. It does not revoke Vale's access at Google, and the cached events stay on your PC. To revoke access, open myaccount.google.com/permissions and remove Vale. To remove the cache, delete %APPDATA%\Vale\calendar-cache.json.
  • Clipboard and notification history. Turning off saving for either one deletes its file.
  • Uninstall. Run irm https://raw.githubusercontent.com/hartono0297/vale/main/uninstall.ps1 | iex. This keeps your data in %APPDATA%\Vale. To delete it too, run $env:DI_PURGE = '1' first, in the same PowerShell window, then the command above.
  • Delete the folder yourself. Removing %APPDATA%\Vale deletes everything Vale keeps there. It does not remove the screenshots you saved, which are in your Windows Screenshots folder, outside that folder. Delete those in File Explorer.

The uninstall script removes Vale's autostart value and the Claude Code hooks Vale added. It never removes the screenshots you saved, the entries Vale added to Mole's whitelist, the settings.json.bak-vale backup, or the access you granted at Google.

Children

Vale is not directed at children under 13. Vale collects nothing from anyone, because there is no Vale server to collect it.
